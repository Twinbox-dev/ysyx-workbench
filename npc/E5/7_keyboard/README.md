# 实验七 状态机及键盘输入 —— 代码导读

这份文档的用法：**假装从空文件开始，分 6 个阶段把现有代码重新"长"出来。**

每个阶段只解决一个问题，都有一个可以亲手验证的里程碑。你可以对着最终代码读，也可以真的删掉重写一遍——后者收获更大，因为每个阶段的卡点你会亲身撞一次。

先跑起来看看目标是什么：

```bash
make DIR=7_keyboard sim    # 91 项断言，几秒钟跑完
make DIR=7_keyboard run    # 图形版本，按键盘看数码管
```

数码管从右往左：`seg1 seg0` 是键码，`seg3 seg2` 是 ASCII，`seg5 seg4` 是按键次数。按住 `A` 显示 `01 61 1C`，松开后低四位熄灭、`01` 留着。LED：`LD0`=Shift `LD1`=Ctrl `LD2`=Alt `LD3`=CapsLock `LD4`=ready `LD5`=overflow。

## 阶段 0：先想清楚要分几层

写代码之前值得先停一下。PS/2 键盘的输入要经过这样一条路：

```
键盘 ──两根线(clk/data)──> ? ──> ? ──> 数码管
     串行的位              字节    "按了A键"
```

中间该切成几块？一个自然的切法是**按抽象层次切两刀**：

```
ps2_keyboard.v    位 → 字节      （懂 PS/2 电气时序，不懂 0xF0 是什么意思）
key_ctrl.v        字节 → 语义    （懂 0xF0 是断码，不碰 ps2_clk）
```

这个分界很关键。`ps2_keyboard.v` 里出现 `0xF0` 就是设计问题，`key_ctrl.v` 里出现 `ps2_clk` 也是。两边用一个简单接口连起来（后面阶段 2 会看到是 `ready`/`nextdata_n`），各自都能单独理解、单独调试。

剩下两块是纯粹的翻译器，没什么状态：

```
scancode2ascii.v  扫描码 → ASCII   （查表）
seg7.v            数字 → 段码       （查表）
```

**里程碑**：能说出"如果显示的 ASCII 不对，我该去查哪个文件"——答案是 `scancode2ascii.v`，因为其他文件根本不知道 ASCII 是什么。

## 阶段 1：把串行的位收成字节

现在只做一件事：`ps2_keyboard.v` 里从 `ps2_clk`/`ps2_data` 还原出 8 位扫描码。先不管 FIFO，收到就直接输出。

### 第一个坑：不能直接用 ps2_clk

`ps2_clk` 是键盘送来的（10–16.7 kHz），和我们的 `clk` 完全异步。新手的第一反应是拿它当时钟：

```verilog
always @(negedge ps2_clk) ...     // ✗ 别这样
```

这在 FPGA 上是坏习惯：`ps2_clk` 没走时钟专用网络，还可能有毛刺，一个毛刺就是一个假时钟沿。标准做法是**只用一个时钟，把异步信号同步进来再检测边沿**：

`ps2_keyboard.v:29-35`

```verilog
reg [2:0] ps2_clk_sync;
always @(posedge clk) ps2_clk_sync <= {ps2_clk_sync[1:0], ps2_clk};
wire sampling = ps2_clk_sync[2] & ~ps2_clk_sync[1];
```

读法：这是一条 3 级移位链，每个 `clk` 把 `ps2_clk` 往里推一格。

- `[0]`、`[1]` 两级负责**同步**：异步信号直接进组合逻辑可能出现亚稳态（既不是 0 也不是 1，持续一小段时间），过两级触发器把概率压到可忽略。
- `[2]` 和 `[1]` 的组合负责**边沿检测**：`[2]==1 && [1]==0` 意思是"再往前一拍是高、后一拍是低"，即下降沿。

`sampling` 是个只持续一拍的脉冲。之后所有接收动作都由它驱动，模块内部就是干净的单时钟同步设计。

> **可迁移的套路**：任何异步输入进 FPGA 都是这个模式——两级同步 + 一级用于边沿检测。记住 `{sync[1:0], in}` 这个写法，后面遇到按键、外部中断都能直接用。

**自测**：为什么用下降沿而不是上升沿？

<details>
<summary>答案</summary>

PS/2 的数据位在时钟下降沿处于**中间位置**，此时电平已稳定半个周期。上升沿正好撞在数据切换的边界上，采到的可能是正在变化的值。讲义里也强调了这点。
</details>

### 拆帧

一帧 11 位：起始位(0) + 8 位数据(**低位在前**) + 奇校验 + 停止位(1)。

`ps2_keyboard.v:78`

```verilog
buffer <= {ps2_data, buffer[9:1]};   // 右移接收
```

为什么是右移？因为低位先到。右移让最先收到的位一路挤到 `buffer[0]`，收满后自然排成：`buffer[0]`=起始位、`buffer[8:1]`=扫描码、`buffer[9]`=校验位。停止位不进 buffer，收到第 11 位时直接看 `ps2_data`。

讲义给的是 `buffer[count] <= ps2_data`（变量索引），两者等价。右移综合出的是一条移位链，而变量索引会综合出 10 选 1 的写使能译码——右移在硬件上更规整。

### 校验

`ps2_keyboard.v:67-69`

```verilog
if ((buffer[0] == 1'b0) &&   // 起始位必须是 0
    (ps2_data == 1'b1) &&    // 停止位必须是 1
    (^buffer[9:1]))          // 奇校验
```

`^buffer[9:1]` 是**归约异或**（reduction XOR），把 9 位（8 位数据 + 1 位校验）全部异或起来。奇校验的定义是"数据位与校验位中 1 的个数为奇数"，所以这 9 位异或应该得 1。一个符号搞定，不用数位数。

三项都通过才算收到一个有效字节——校验失败就整帧丢弃，这比收进来一个错误值安全。

**里程碑**：此时把 `buffer[8:1]` 直接接到两个数码管上，按 `A` 键应该能看到 `1C` 闪一下。虽然还没有 FIFO，快速连按会丢键，但**通信链路已经通了**。

**如果看不到正确值，按这个顺序查**（这也是讲义建议的调试顺序）：

| 现象 | 大概率原因 |
|---|---|
| 完全没反应 | `sampling` 从未为 1 → 检查 `ps2_clk` 有没有接对 |
| 值一直是 0 | 校验永远失败 → 把三个条件分别引到 LED 上看哪个不满足 |
| 值大致对但偶尔错乱 | 帧边界错位 → 检查 `count` 是否在 10 时正确归零 |
| 值是正确值的位反转 | 收错了方向 → 右移写成了左移 |

先把 `sampling` 引到 LED 上确认它在跳，这一步能省很多时间。

## 阶段 2：加 FIFO 和握手

现在的问题：键盘按帧送数据，上层按周期处理，快慢不匹配。上层还没处理完，下一帧就来了 → 丢键。

解法是加缓冲。这是数字系统里的通用场景，标准答案是 **FIFO 队列**。

### 环形队列

`ps2_keyboard.v:44-45`

```verilog
reg [7:0] fifo [0:7];
reg [2:0] w_ptr, r_ptr;
```

读写指针都是 3 位，加到 7 之后**自动回绕**到 0——用位宽实现取模，不需要显式的 `if (ptr == 8) ptr = 0`。这是个很常用的技巧，前提是深度必须是 2 的幂。

`ready` 的语义是"队列非空"，即 `w_ptr != r_ptr`。

**这里有个容易忽略的细节：8 个槽实际只能用 7 个。** 如果写满 8 个，`w_ptr` 会绕回等于 `r_ptr`，和"空"的条件撞车、无法区分。环形 FIFO 的标准解法就是牺牲一个槽位（另一种做法是给指针多加一位来区分绕回）。

**自测**：如果真的写进 8 个字节会发生什么？

<details>
<summary>答案</summary>

`w_ptr` 绕回等于 `r_ptr`，`ready` 变成 0——队列看起来是"空"的，8 个字节全都读不出来。代码里用 `overflow` 标志记录这种情况发生过（`ps2_keyboard.v:73`），但不阻止它。
</details>

### 握手：脉冲还是电平

上层怎么告诉 FIFO"我取走了"？看 `key_ctrl.v` 这一侧：

`key_ctrl.v:56-65`

```verilog
always @(posedge clk) begin
    if (rst)                  state <= S_IDLE;
    else if (state == S_IDLE) state <= ready ? S_ACK : S_IDLE;
    else                      state <= S_IDLE;      // 立刻回 IDLE
end

assign nextdata_n = (state == S_ACK) ? 1'b0 : 1'b1;
```

这是个只有两个状态的状态机，`S_ACK` 只停留**一拍**。

**为什么必须立刻回 `S_IDLE`？** 因为 `nextdata_n` 必须是脉冲。如果停在 `S_ACK` 持续拉低，`ps2_keyboard` 会每拍都推进读指针，把队列瞬间抽空。

> **可迁移的坑**：握手协议里"脉冲"和"电平"含义完全不同。看到 `xxx_n` 这类确认信号，先问一句"它该持续多久"。这个坑在总线协议里也很常见。

`byte_valid` 是这个阶段最有用的产物：

`key_ctrl.v:65`

```verilog
wire byte_valid = (state == S_ACK);
```

意思是"本拍 `data` 上有一个有效新字节"。因为 `ps2_keyboard` 要到 `S_ACK` 周期末才推进读指针，`data` 在整个 `S_ACK` 期间是稳定的，可以放心用。后面所有逻辑都以它为使能条件。

### 一处刻意利用赋值顺序的写法

`ps2_keyboard.v:59-72`，同一个 `always` 块里 `ready` 被赋值了两次：

```verilog
if (ready && (nextdata_n == 1'b0)) begin
    r_ptr <= r_ptr + 3'd1;
    if (w_ptr == (r_ptr + 3'd1)) ready <= 1'b0;   // 取走后队列变空
end
if (sampling) begin
    ...
        ready <= 1'b1;                             // 同时又有新数据入队
```

非阻塞赋值里**后面的覆盖前面的**。所以"取走最后一个字节"和"新字节入队"同拍发生时，结果是 `ready` 保持 1——正是我们想要的（队列里确实有新数据）。

这不是巧合，是刻意的。这类写法很省事但容易读错，所以代码里标了注释。**读别人代码时看到同一个信号在一个块里被多次赋值，要留意顺序。**

**里程碑**：快速连按多个键不丢键码。把 `ready` 引到 LED 上，按键时应该看到它闪。

## 阶段 3：识别通码与断码

现在能收到字节了，但还不知道含义。按下再放开 `A`，收到的是三个字节：`1C F0 1C`。

规则：
- `0xF0` 是**断码前缀**，表示"下一个字节对应的键被放开了"
- `0xE0` 是**扩展键前缀**，用于右 Ctrl、方向键等
- 两者可叠加：`E0 F0 xx` = 放开一个扩展键

这需要状态机记住"前面收到过什么前缀"。

`key_ctrl.v:68-91`

```verilog
localparam P_NORMAL  = 2'b00;
localparam P_EXT     = 2'b01;   // 收到 0xE0
localparam P_BRK     = 2'b10;   // 收到 0xF0
localparam P_EXT_BRK = 2'b11;   // 收到 0xE0 0xF0
```

用 2 位编码正好表示 4 种组合，**每个前缀占一位**，所以判断时直接看对应位：

```verilog
wire is_ext = (prefix == P_EXT) || (prefix == P_EXT_BRK);
wire is_brk = (prefix == P_BRK) || (prefix == P_EXT_BRK);
wire is_key = byte_valid && !is_e0 && !is_f0;   // 是键值，不是前缀
```

状态转移只有三条规则：

```verilog
if (is_e0)      prefix <= P_EXT;                       // 记下扩展前缀
else if (is_f0) prefix <= is_ext ? P_EXT_BRK : P_BRK;  // 叠加断码前缀
else            prefix <= P_NORMAL;                    // 收到键值，序列结束
```

跟一遍 `1C F0 1C`：

| 收到 | 进入时的 prefix | is_brk | 动作 |
|---|---|---|---|
| `1C` | `P_NORMAL` | 0 | 通码 → `key_down=1`，计数 +1 |
| `F0` | `P_NORMAL` → `P_BRK` | — | 只记前缀，不产生动作 |
| `1C` | `P_BRK` | 1 | 断码 → `key_down=0` |

### 左右 Ctrl 的扫描码是一样的

左 Ctrl 和右 Ctrl **都是 `0x14`**，区别只在右 Ctrl 带 `E0` 前缀。所以判断时必须把前缀一起比较：

`key_ctrl.v:97-98`

```verilog
wire hit_lctrl = is_key && !is_ext && (data == 8'h14);
wire hit_rctrl = is_key &&  is_ext && (data == 8'h14);
```

这也解释了扩展前缀为什么存在：第二套扫描码只有 8 位，不够分给所有按键，于是用 `E0` 开辟第二个编码空间。

**里程碑**：按住键时数码管显示键码，松开时熄灭。

**自测**：如果把 `is_key` 的定义写成 `byte_valid`（去掉两个前缀判断），会发生什么？

<details>
<summary>答案</summary>

`0xF0` 和 `0xE0` 本身会被当成键值处理。按一次 `A` 会看到数码管先显示 `1C`、再显示 `F0`、再显示 `1C`，按键次数也会多计。前缀字节必须被"吃掉"，不能当键值。
</details>

## 阶段 4：ASCII 转换

纯查表，`scancode2ascii.v`。这一阶段没有时序，但有两个设计决策值得看。

### 一个表项存两种情况

`scancode2ascii.v:30,58`

```verilog
8'h1C, 16'h6141,   // A 键：不按 Shift 是 'a'(0x61)，按 Shift 是 'A'(0x41)
8'h16, 16'h3121,   // 1 键：'1'(0x31) / '!'(0x21)
```

每项 16 位，把"无 Shift"和"有 Shift"两个 ASCII 打包在一起。查一次表拿到两种结果，再用一个 mux 选，比查两张表省事。

`default_out` 为 0 表示查不到，输出 `valid=0`——这就是方向键、F1 等非字符键 ASCII 位熄灭的依据。显示 `00` 会误导（让人以为 ASCII 真是 0）。

### Caps Lock 只影响字母，且与 Shift 抵消

`scancode2ascii.v:95-96`

```verilog
wire is_letter = (ascii_normal >= 8'h61) && (ascii_normal <= 8'h7A);
wire use_shift = shift ^ (caps & is_letter);
```

两个决策：

1. **`is_letter` 的判据是"未按 Shift 时的 ASCII 落在 `a`–`z`"**，而不是枚举字母键的扫描码。这样加新按键时不用改这段逻辑——数据驱动，逻辑不动。
2. **用异或而不是或**。Caps 开着时再按 Shift 应该得小写（两者抵消），这正是异或的语义。写成 `|` 就错了。

**自测**：Caps Lock 开启时按 `1` 键，显示什么？为什么？

<details>
<summary>答案</summary>

显示 `31`（字符 `1`）。因为 `1` 键的 `ascii_normal` 是 `0x31`，不在 `a`–`z` 范围内，`is_letter=0`，所以 `caps` 被 `&` 掉了、不起作用。这正是 `is_letter` 存在的目的——Caps Lock 不该把 `1` 变成 `!`。
</details>

## 阶段 5：组合键与按键计数

最后一个阶段，也是坑最多的一个。

### Shift/Ctrl/Alt：跟随通码断码即可

`key_ctrl.v:118-123`

```verilog
if (hit_lshift) lshift <= ~is_brk;   // 通码置 1，断码置 0
```

这些是"按住有效"的**电平型**状态。键盘按住不放会重复发通码，但重复置 1 是**幂等**的，没有副作用。

### Caps Lock：这里有个真实的 bug

Caps Lock 不一样，它是**锁定键**——按一次翻转一次。直觉写法：

```verilog
if (hit_caps && !is_brk) capslock <= ~capslock;    // ✗ 有 bug
```

问题：键盘按住不放会持续重复发送通码（typematic repeat），这段代码会让 `capslock` **疯狂翻转**。按住 Caps 一秒钟，它可能翻转几十次，松手后是开还是关完全随机。

正确写法要加一个"是否已按住"的寄存器做边沿检测：

`key_ctrl.v:106,128-131`

```verilog
reg caps_held;
if (hit_caps) begin
    caps_held <= ~is_brk;
    if (!is_brk && !caps_held) capslock <= ~capslock;   // 只在按下的那一次
end
```

> **这是本实验最值得记住的一课：分清"电平型状态"和"边沿型状态"。** 前者跟随输入（Shift），重复赋值无害；后者需要记住上一个状态才能识别"变化的那一瞬间"（Caps Lock）。看到"按一次翻转"这类需求，就要想到边沿检测。

### 按键计数：同一个坑的另一面

typematic repeat 也会让计数虚高。判断"是不是新的键"：

`key_ctrl.v:153`

```verilog
wire same_key = key_down && (key_code == data) && (held_ext == is_ext);
```

三个条件都必要：
- `key_down` — 当前确实有键按住
- `key_code == data` — 键码相同
- `held_ext == is_ext` — **扩展位也相同**

第三条是为了防止右 Ctrl（`E0 14`）和左 Ctrl（`14`）互相误判，所以 `held_ext` 要和 `key_code` 一起锁存。

### 组合键为什么不冲突

选做要求"Shift 与字母键同按互不冲突"。看实现：

`key_ctrl.v:154-155`

```verilog
wire key_make  = is_key && !is_modifier && !is_brk;
wire key_break = is_key && !is_modifier &&  is_brk;
```

组合键被 `!is_modifier` 挡在外面——它们**只更新自己的状态位，完全不碰 `key_code` 和 `key_count`**。两条路径天然独立，不需要额外处理冲突。

这是个好例子：**需求听起来要特殊处理，但只要分层分对了，它自动就成立了。**

### 放开时也要检查 same_key

`key_ctrl.v:176-179`

```verilog
else if (key_break) begin
    if (same_key) key_down <= 1'b0;   // 只有放开的正是当前按住的键才熄灭
end
```

否则：先按 `A`、再按 `S`、然后放开 `A` —— 正在显示的 `S` 会被误熄灭。

### ASCII 在按下瞬间锁存

`key_ctrl.v:169`

```verilog
key_ascii <= ascii;   // 而不是让数码管直连组合逻辑
```

这样按 `Shift+A` 显示 `41` 后，即使松开 Shift（`A` 还按着），显示也不跳变成 `61`。**锁存的是"按下那一刻的解释结果"**，符合直觉。

**里程碑**：全部功能正常。此时跑 `make DIR=7_keyboard sim` 应该 91 项全过。

## 调试实录：三个真实的 bug

这三个都是实现过程中真实踩到的，不是编出来的教学例子。它们的共同点是**单看代码很难发现，但测试一跑就暴露**。

### bug 1：Caps Lock 被重复通码反复翻转

| | |
|---|---|
| **现象** | 按一下 Caps Lock，LED 指示时亮时不亮，行为随机 |
| **怎么定位** | 写测试模拟"按住 Caps 不放"（连发三次通码），断言 `capslock` 只应翻转一次 |
| **根因** | typematic repeat 让通码重复到达，`capslock <= ~capslock` 每次都执行 |
| **修法** | 加 `caps_held` 寄存器做边沿检测（阶段 5） |
| **教训** | 锁定型状态必须边沿触发；键盘会重复发通码这件事，协议文档里不显眼但影响很大 |

### bug 2：测试模型自己把 bug 掩盖了

这个最值得讲，因为它关于**测试本身可能是错的**。

nvboard 的键盘模型和讲义的模型时序不一样。讲义模型是"空闲高电平，需要时拉低"；nvboard 是每 10 周期无条件**翻转** `PS2_CLK`：

```cpp
// nvboard/src/keyboard.cpp
ps2_clk = !ps2_clk;
pin_poke(PS2_CLK, ps2_clk);
if (ps2_clk) { /* 只在翻转成高时放数据位 */ }
```

翻转成高时放数据，翻转成低时留给 DUT 采样。**所以 `ps2_clk` 的初值决定第一个边沿是上升还是下降**：

- 初值 0 → 第一个边沿是上升沿 → 先放数据、后采样 ✅
- 初值 1 → 第一个边沿是下降沿 → DUT 多采一位 → **整帧永久错位** ❌

我最初在 nvboard 主程序里写的是 `ps2_clk = 1`（因为"PS/2 空闲电平是高"的直觉），这是错的。

但真正的问题在测试上。我写的复现模型是**直接赋值**：

```cpp
dut->ps2_clk = 1;    // ✗ 每次都赋成 1
```

这个模型**测不出上面的问题**——不管初值是什么，第一次赋值就把相位强行拉正了。测试通过，但什么也没验证。

改成和 nvboard 一致的翻转后：

```cpp
dut->ps2_clk = !dut->ps2_clk;   // ✓ 初值才真正起作用
```

再故意把初值改成 1，测试立刻失败。这才证明测试真的在测这件事。

> **教训：能通过的测试不等于有效的测试。** 仿真模型必须忠实复现真实环境的行为，"差不多"的模型会给你虚假的安全感。

### bug 3（来自实验八，但同类）：用无效信号做时间标记

实验八里我用 `(h_addr==0 && v_addr==0)` 判断"一帧开始"，看起来很合理。但**消隐期这两个信号都被强制清零**，该条件在垂直消隐的每一行都成立一次——本该每帧动一次的方块，实际每帧动了 45 次。

教训是通用的：**某些信号只在特定区间有效，不能用它们的取值来标记时间点**，除非那个取值只在有效区出现。

## 为什么测试和 Verilog 差不多长

`main.cpp` 是 487 行，`vsrc/` 全部 Verilog 是 588 行（其中 58 行是复制来的 `mux.v` 库、52 行是纯查找表数据）。测试几乎和实现一样长，这个比例不是浪费。

### 这类实验没法靠眼睛调

前面几个实验（mux、ALU、移位器）是组合逻辑，输入输出一一对应，错了立刻看得出来。这个实验不一样：

- 输入是**异步串行**的，中间要经过同步、边沿检测、拆帧、校验、FIFO、前缀状态机六道处理
- 任何一步错了，最终表现都只是"数码管显示了个奇怪的值"，**反推不回去**
- 上板一次要几分钟生成 bitstream，而你看到的只有最终现象

所以时间不是花在写代码上，是花在**建立观测手段**上。讲义其实在提示这件事，只是说得轻：

> 建议先将键盘控制模块的 ready、sampling 或 overflow 等重要信号引至顶层模块用 LED 显示，确保键盘基本通信正常。

这就是"先建观测点，再调功能"。这份实现把 `ready`（LD4）和 `overflow`（LD5）都引出来了。

### 三个具体做法

**1. 软件参考模型**：用 C++ 独立算出期望值，和 DUT 逐项比对。

比如按下 `A` 应该显示什么，测试里是写死的期望值 `0x1C`/`0x61`，不依赖 DUT 的行为。**期望值必须独立推导，不能从 DUT 里读出来再比对自己** —— 那样恒等成立、什么也没测。

**2. 反解显示内容**：`seg_decode()` 把段码反查回十六进制数字。

这样断言可以写成"数码管上显示的是 `0x1C`"，而不是比较一串原始段码 `0x8F`。**测试代码贴近人的意图，比贴近信号更容易维护**——半年后回来看，前者一眼能懂。

**3. 故障注入**：验证测试真的在测它声称的东西。

做法很简单：故意改坏一处，看测试是否失败。bug 2 就是这么发现的。花一分钟，就能区分"测试通过"和"测试有意义"。

如果你打算重做一遍练手，**建议先写测试再写实现**——不是为了规范，是因为这个实验真的没法靠眼睛调。

### 一处诚实的说明

`overflow` 这条路径**实际没有测试覆盖**。两处断言都只验证它是 0（`main.cpp:337,432`），从没真正触发过，所以 `LD5` 恒灭。功能验收不要求这个，但如果被问"FIFO 溢出时怎么处理"，手上没有实测证据。这是下面练习 4 的内容。

## 动手改（按难度排列）

改的时候随时跑 `make DIR=7_keyboard sim` 验证。

1. **扩充 ASCII 表**：加小键盘按键。注意小键盘的 `/` 和 `Enter` 是扩展键（`E0` 前缀），而当前查找表只用 `code` 做键、没考虑 `is_ext`——你需要想想怎么把扩展位也纳入查表的键。
2. **按键次数改十进制**：目前是十六进制，按 10 次显示 `0A`。改成 BCD 计数器让它显示 `10`。
3. **显示历史键码**：讲义建议的调试手法——用移位寄存器保存最近 3 个键码，按一次 `A` 应显示 `1C F0 1C`。可以复用 `6_shifter` 的移位寄存器。
4. **补上 overflow 测试**：连续快速送入 8 个以上字节而不取走，验证 `overflow` 置位。注意"8 个槽只能用 7 个"。这是上面提到的覆盖缺口。
5. **把 sampling 引到 LED**：讲义建议的三个观测点里，目前只引了 `ready` 和 `overflow`。
6. **改成 one-hot 编码**：把 `prefix` 状态机改成 one-hot，用 `yosys` 对比综合后的资源占用（触发器数 vs 组合逻辑），验证讲义关于编码取舍的说法。
7. **Mealy vs Moore**：当前输出都只由状态和锁存值决定（Moore 型）。把 `key_down` 改成 Mealy 型（直接依赖当前输入字节），观察它提前一拍变化，以及这给数码管显示带来什么麻烦。这正好是讲义留的思考题。
